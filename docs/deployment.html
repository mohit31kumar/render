Deployment

Host Render Monitor on Render itself: a backend web service, a frontend static site (or web service), and a GitHub Actions workflow to keep free-tier services awake.

Backend service

Create a Web Service on Render pointing at the repo root.

⚠

Don’t set PORT manually

Render injects PORT at runtime. Setting it yourself can prevent the service from binding correctly.

Replace <backend> with your actual backend hostname and omit any trailing slash. Changing these variables requires a rebuild for static sites because Vite embeds them in the bundle.

GitHub keep-alive

Free-tier Render web services suspend after a period of inactivity. The repository includes .github/workflows/render-keep-alive.yml, which pings your backend every five minutes.

  1. Confirm the workflow exists

    .github/workflows/render-keep-alive.yml

  2. Add repository secrets

    Go to Settings → Secrets and variables → Actions and create:

    • RENDER_URL — backend URL, e.g. https://render-backend-abc1.onrender.com (no trailing slash).
    • FRONTEND_URL — optional; set only if the frontend is a Web Service.

  3. Let it run

    The cron */5 * * * * pings $RENDER_URL/health, and $FRONTEND_URL/ when configured. You can also trigger it manually from the Actions tab.

⚠

GitHub may delay scheduled workflows under load, so the five-minute interval is best-effort. A Static Site needs no keep-alive ping.

Verification

  1. Backend health

    curl https://<backend>/health
# {"status":"ok"}

  2. Render connection

    curl https://<backend>/api/render/connection/status
# {"connected":true}

  3. Frontend

    Open https://<frontend>/ and confirm the dashboard loads with no proxy or CORS errors in the console.

  4. Keep-alive

    Check the Actions tab to confirm the Render Keep-Alive workflow runs successfully, and that the frontend ping is either performed or intentionally skipped.

Troubleshooting

Symptom Fix
Frontend calls the wrong host Rebuild after changing VITE_API_URL / VITE_WS_URL; Vite embeds them at build time.
CORS errors in the browser Confirm the backend is running and the frontend uses the backend URL, not a local path.
Backend returns 401 RENDER_API_KEY is missing or wrong in the Render environment.
Keep-alive workflow fails RENDER_URL secret is missing or has a trailing slash / wrong scheme.
Service sleeps despite the workflow GitHub delayed the schedule; trigger a manual run or shorten the interval.
Web service won’t start Don’t set PORT manually; check the start command and build logs.

See also security considerations before exposing the backend publicly.
