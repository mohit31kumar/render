Setup guide

Get Render Monitor running on your machine in a few minutes. This guide covers prerequisites, the backend, the frontend, environment variables, and verification.

Prerequisites

  • Node.js 18+ (Node 20 LTS recommended) and npm.
  • A Render account with at least one service.
  • A Render API key — created in the next step.
  • Git, to clone the repository.
git clone https://github.com/mohit31kumar/render.git
cd render

1. Get a Render API key

  1. Sign in to dashboard.render.com.
  2. Open Account Settings → API Keys (or go to dashboard.render.com/u/settings).
  3. Create a new API key and copy it. Keys look like rnd_xxxxxxxx….
⚠

Keep the key secret

The key grants read access to your whole Render account. Never commit it and never paste it into client-side code — Render Monitor sends it to the backend only.

2. Set up the backend

The backend is an Express server that proxies the Render REST and WebSocket APIs.

cd server
npm install
cp .env.example .env

Edit server/.env and set your key:

PORT=3001
RENDER_API_KEY=rnd_your_real_key_here
NODE_ENV=development

3. Set up the frontend

The frontend is a Vite + React SPA that talks to the backend.

cd ../client
npm install
cp .env.example .env

Point the client at the local backend in client/.env:

VITE_API_URL=http://localhost:3001/api/render
VITE_WS_URL=http://localhost:3001
VITE_APP_ENV=development
ℹ

Dev proxy alternative

The Vite dev server also proxies /api to http://localhost:3001, so VITE_API_URL=/api works if you prefer same-origin requests during development.

4. Run locally

Open two terminals.

Terminal A — backend

cd server
npm run dev

Serves http://localhost:3001.

Terminal B — frontend

cd client
npm run dev

Serves http://localhost:5173.

5. Verify

  1. Check the backend health

    curl http://localhost:3001/health
# {"status":"ok"}

  2. Check the Render connection

    curl http://localhost:3001/api/render/connection/status
# {"connected":true}

    A {"connected":false} response usually means a missing or invalid RENDER_API_KEY.

  3. Open the app

    Visit http://localhost:5173. The dashboard should load with your services and no proxy errors in the browser console.

Environment variables

Backend — server/.env

Name Required Default Description
RENDER_API_KEY Yes — Render API key. Server-side only.
PORT No 3001 Port to listen on. Render injects this in production.
NODE_ENV No development development or production.

Frontend — client/.env

Name Required Description
VITE_API_URL Yes Backend API base, e.g. https://<backend>.onrender.com/api/render.
VITE_WS_URL Yes Backend origin for the log stream, e.g. https://<backend>.onrender.com.
VITE_APP_ENV No development or production.
⚠

Do not add a trailing slash to VITE_API_URL or VITE_WS_URL. Vite embeds VITE_* variables at build time.

Troubleshooting

Symptom Likely cause & fix
{"connected":false} Missing or invalid RENDER_API_KEY. Verify the key and restart the backend.
Missing RENDER_API_KEY The backend can’t see the variable. Confirm server/.env exists and was loaded.
429 / rate limit errors Too many requests to Render. Slow queries down or wait for the rate-limit window to reset.
Logs page says “Multiple workspaces found” Your API key spans more than one workspace. Pass an explicit ownerId (see the API reference).
Frontend shows network errors Backend isn’t running, or VITE_API_URL points to the wrong host/port.
Log stream won’t connect Check VITE_WS_URL. It must be the backend origin, not the API path.

Still stuck? Check the API reference or the architecture overview.
